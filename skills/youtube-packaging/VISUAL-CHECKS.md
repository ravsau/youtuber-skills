# Visual checks and example

## Evidence and meaning

- For each factual or implied title/image claim, name the footage timestamp or real asset that supports it. Include implied claims about a result, error, speed, savings, or tool identity.
- Use genuine screenshots as proof. Crop or enlarge them honestly. Never fabricate a benchmark, receipt, dashboard, success state, or captured footage. Label conceptual art clearly and keep it visually distinct from evidence.
- First ask someone unfamiliar with the video what the image seems to show with the title hidden, then what result they expect with the title restored. Simplify any misunderstanding. If nobody checks it, label the response an editorial prediction, not user testing.

## Feed and design

- Preview title and thumbnail together at small feed size among comparable videos, on both light and dark backgrounds. Include the duration badge and title truncation; check that the subject and reason to watch remain clear without enlarging. Treat preview sizes as stress tests, not universal device dimensions.
- Prefer a dominant accent that separates the concept from its actual neighbors while keeping text and subjects readable. Red, white, and black are allowed; judge contrast and context rather than banning a hue or requiring a specific size. Avoid visual complexity that overwhelms the idea.
- Choose a face-led or object-led concept according to what carries the story. Use only a real, supplied photo when creator identity or expression helps; otherwise use a relevant object, screen, or proof asset. Capture useful real frames of the face, hardware, and result during filming when available. Never invent the creator's appearance.
- Develop different ways to express the same deliverable promise before polishing decoration. A concept should test an editorial idea such as real proof, the workflow, or a consequence; it is not a proven high-performing template.

## Example

Example input (with these assets supplied): `Show how I recover an edit an AI coding agent overwrites; screen recording contains the actual diff and recovery steps; no face footage.`

| Title | Thumbnail concept | Image text | Gate and editorial note |
|---|---|---|---|
| How I Recover an Edit an AI Agent Overwrites | Crop from the supplied recording showing the real diff, with the changed lines legible | `MY EDIT / AGENT CHANGE` | Pass if the shown diff and recovery are in the video; test at feed size. The label clarifies the evidence but is not a performance claim. |

Image prompt: Create a 16:9 thumbnail layout using the supplied real diff capture as the sole proof asset. Preserve the visible content; crop only to enlarge it without changing what it shows. Add the exact label `MY EDIT / AGENT CHANGE` in a clear open area. Use a dominant accent that contrasts with the neighboring thumbnails supplied for review, readable light and dark tones, and no face. Do not generate interface text, a result, or extra proof. No watermark.

This is an editorial concept example, not user research or a performance benchmark.

## Breakout medians (checklist, not gate)

vidIQ studied 500 breakout long-form videos across 30 niches (June 2026): 69% of thumbnails show a face, 56% use high-contrast color, 89% use at least one of the two, and thumbnails with text hold a median of 5 words. [source: vidiq.com/blog/post/youtube-thumbnail-design-tips] Use these as a prompt, not a rule: if a concept has no face and no strong contrast, say why the object carries it. If the text runs past 5 words, cut or justify. Feed context still wins over any median.
